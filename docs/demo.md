# 5 分钟演示

先按 setup 准备本机环境，登录自己的管理员。所有操作均为合成演示业务，审核动作必须来自可信交互式会话。模型没有 approve 工具。

1. 在 `/api/after-sales/workbench` 选择“窗口内损坏”并创建独立实例，记下新订单号。不要改原订单日期；原 ORD-2026-0017 窗口已结束。
2. 无模型演示可直接在工作台提交资料；Agent 演示可在 `/workspace/chats/new` 告知新订单号、明确问题、证据说明与“补发”偏好。每次续办要求读取最新工单。
3. 如需图片，手动上传单帧 PNG/JPEG/WebP，由管理员查看并核验。系统验证格式与哈希，不能声称模型识别了损坏。
4. 生成方案后观察 awaiting_approval、工单号、方案号、政策引用。管理员核对并批准；客户说“同意”不能替代审批。
5. 可在执行前修改证据，观察 revision 变化和旧方案失效。重新生成并人工批准后，要求 Agent 继续；演示操作应回读 resolved，重复执行返回同一操作。

签收冲突场景应 manual_review，不生成可执行方案。物流停滞的已批调查执行后 awaiting_followup；管理员记录明确标记的合成最终结果后结束。

真实模型演示会产生供应商费用，应先限定场景和消息/API规模，按每 run usage 核对；工具错误、usage 缺失、循环或达到原响应后累计阈值时停止后续请求，不靠反复重试换取成功。工作台展示与历史验证材料不需要新模型调用。

演示重点不是“全自动退款”，而是证明身份可信、规则可核对、人工权限不能被模型代替，以及失败时能安全停止。
